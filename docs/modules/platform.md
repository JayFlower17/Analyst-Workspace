# 模块说明：platform

## 1. 模块定位

`platform` 不是单独的一段代码，而是整个项目的产品级视角。

它描述的是：

- 这个系统想解决什么问题
- 用户如何进入系统并完成分析
- 各个模块为什么存在
- 模块之间如何组成一条完整主线

一句话定义：

**这是一个以聊天为入口、以 workspace 为组织单元、以 DuckDB 为执行底座的智能数据分析平台。**

---

## 2. 负责什么

`platform` 负责定义全局主线：

1. 用户登录进入系统
2. 上传数据集
3. 在聊天中做探索式分析
4. 将数据沉淀到 workspace
5. 在 workspace 中做更正式的多表分析
6. 保存分析结果与摘要，形成可回看的资产

---

## 3. 不负责什么

`platform` 不负责具体实现细节，例如：

- 不直接负责登录逻辑
- 不直接负责 SQL 生成
- 不直接负责文件上传
- 不直接负责 Python 执行

这些职责属于下面的具体模块。

---

## 4. 当前主流程

当前项目实际已经形成两条主要路径：

### 路径 A：探索式分析

`login -> chat -> 上传数据 -> 提问 -> 返回结果`

适合：

- 快速试数据
- 单表分析
- 临时问答式探索

### 路径 B：正式分析

`chat / datasets -> workspace -> 多表分析 -> 结果沉淀`

适合：

- 多表联合分析
- 业务上下文更明确的分析任务
- 需要描述、关系、结果复用的场景

---

## 5. 当前问题

平台层面目前最大的几个问题是：

1. 两套前端并存，主线不够统一
2. `workspace / workplace` 术语混用
3. artifact 能力还没有真正进入用户心智
4. 模块已经开始分层，但文档和命名还没完全同步

---

## 6. 后续演进方向

平台层面后续只保留一条清晰主线：

1. `frontend-next/` 成为唯一前端主线
2. `chat` 成为探索入口
3. `workspace` 成为正式分析单元
4. `analysis artifact` 成为结果沉淀中心
