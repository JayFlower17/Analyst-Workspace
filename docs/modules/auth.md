# 模块说明：auth

## 1. 模块定位

`auth` 模块负责用户身份识别和接口访问控制。

它是整个平台所有受保护能力的入口前提。

---

## 2. 负责什么

- 用户注册
- 用户登录
- JWT token 生成与校验
- 受保护接口访问控制
- 用户基础角色信息维护

---

## 3. 不负责什么

- 不负责业务级权限编排
- 不负责聊天、分析、数据集等具体业务
- 不负责前端登录页样式

---

## 4. 当前状态

当前已具备：

- 注册
- 登录
- JWT 返回
- 前端 token 持久化接入

目前角色概念存在，但系统核心仍以“登录可用”为主，不是复杂 RBAC 平台。

---

## 5. 当前问题

1. 新前端鉴权闭环还未完全补齐
2. 角色能力目前没有真正展开
3. 前后端认证体验需要进一步统一

---

## 6. 后续演进方向

短期：

- 先保证 `frontend-next/` 的登录注册和 token 流程完整可用

中期：

- 再考虑角色差异化能力
- 明确 admin 和普通用户的后台管理边界
