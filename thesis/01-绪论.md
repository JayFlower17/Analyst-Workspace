# 第 1 章 绪论

## 1.1 研究背景

随着数字化转型的不断推进，企业、高校及各类组织在日常运行过程中积累了大量数据。这些数据既包括数据库、电子表格等结构化数据，也包括文档说明、业务规则、会议纪要、制度文件等非结构化数据。如何对这些多源异构数据进行高效分析，已经成为支撑决策的重要问题。

传统数据分析工具通常依赖人工编写 SQL、使用商业智能工具构建报表，或依赖专业分析人员进行数据清洗与建模。这类方式虽然在固定场景下具有较高稳定性，但也存在明显不足：一是对使用者的数据能力要求较高，普通业务人员往往难以直接使用；二是分析过程通常仅针对结构化数据，难以充分利用非结构化文档中的规则说明与业务语义；三是分析结果多停留于一次性查询或静态报表，缺少持续沉淀和复用机制。

近年来，大语言模型在自然语言理解、代码生成和任务规划方面展现出显著能力，使“用自然语言驱动数据分析”成为可能。基于大语言模型的数据分析系统能够根据用户问题自动生成 SQL 或 Python 代码，并结合数据结构信息输出分析结果。这为降低数据分析门槛、提升分析效率提供了新的思路。然而，单纯依赖自然语言转 SQL 的方案仍存在局限，尤其在面对多表联合分析、业务规则约束以及非结构化上下文参与分析时，系统往往难以稳定输出高质量结果。

基于此，设计一个融合 AI 智能体、结构化数据处理、非结构化文档检索和交互式工作区管理能力的数据分析系统，具有较强的研究价值和实际意义。

## 1.2 研究意义

本课题的研究意义主要体现在以下几个方面。

首先，在应用层面，本课题能够降低数据分析系统的使用门槛。传统分析流程对 SQL 编写能力和数据建模经验依赖较强，而交互式智能分析系统可以让用户通过自然语言提出问题，由系统自动生成分析逻辑并返回结果，从而使更多非技术人员能够参与数据分析过程。

其次，在技术层面，本课题探索了结构化数据与非结构化文档联合分析的实现路径。现实业务分析过程中，结构化数据往往只能反映“发生了什么”，而业务文档、规则说明和口径定义则回答“应该如何理解这些结果”。将二者统一纳入分析上下文，有助于提升分析结果的准确性、可解释性和业务一致性。

再次，在系统设计层面，本课题将 AI 智能体机制引入交互式数据分析流程，通过问题理解、上下文组织、分析执行和结果反馈等环节的协同，实现从“用户提问”到“结果输出”的端到端闭环。这对于智能分析系统的工程化实现具有参考意义。

最后，在研究与教学层面，本课题可为面向大语言模型的数据分析平台设计提供一个可验证、可扩展的原型系统，为后续关于智能体分析框架、联合检索机制和评测体系的研究提供基础。

## 1.3 国内外研究现状

目前，围绕智能数据分析的研究主要集中在自然语言查询、知识增强检索以及智能体任务编排等方向。

在自然语言数据分析方面，国外较早开展了 NL2SQL 相关研究，通过语义解析、模板匹配或神经网络模型实现从自然语言到 SQL 的转换。随着大语言模型的发展，基于提示工程和上下文注入的分析系统逐渐兴起。这类系统能够在较少规则约束下生成可执行查询，在探索式数据分析中表现出较高灵活性。然而，许多研究主要聚焦单表或相对简单的结构化任务，对于多表关系、业务规则和非结构化信息利用不足。

在知识增强检索方面，检索增强生成（Retrieval-Augmented Generation，RAG）技术已经广泛应用于问答系统、知识库系统和文档助手中。其主要思路是将文档切分为多个片段，通过向量检索或关键词检索召回相关内容，并将召回结果与用户问题一起输入模型。该类方法在非结构化知识利用方面具有明显优势，但通常偏重文本理解，较少与结构化分析执行链路深度耦合。

在智能体系统方面，近年来出现了较多基于大语言模型的 Agent 框架。这类系统通过任务规划、工具调用和结果验证等机制，使模型具备更强的复杂任务执行能力。在数据分析场景中，智能体可用于问题路由、上下文选择、SQL 或 Python 生成以及结果解释等环节。但现有研究中，真正将结构化分析、文档检索、上下文编排和交互式工作区组织整合为统一系统的案例仍然相对有限。

综上所述，当前研究已经为智能分析系统提供了自然语言处理、知识检索和智能体执行等技术基础，但在多源异构数据统一组织、联合上下文分析以及交互式分析平台工程化实现方面，仍有较大研究和实践空间。

## 1.4 本文研究内容

围绕上述问题，本文设计并实现了一个基于 AI 智能体的交互式数据分析系统。系统以工作区为核心组织单元，支持结构化数据集与非结构化文档的统一管理，并通过 AI 智能体完成分析请求理解、上下文组装、执行路径生成和结果返回。

本文的主要研究内容包括：

1. 设计交互式数据分析系统总体架构，明确前端交互层、后端服务层、数据存储层和分析执行层的职责边界。
2. 实现结构化数据导入与管理功能，支持 CSV、Excel 等文件上传、元数据提取与 DuckDB 表管理。
3. 实现非结构化文档处理功能，支持 TXT、Markdown、PDF、DOCX 等文档解析、分块存储与检索。
4. 设计工作区机制，将数据表、文档、关系和分析结果纳入统一上下文空间，支持正式分析与结果沉淀。
5. 实现基于 AI 智能体的分析链路，使系统能够根据用户自然语言问题生成 SQL 或 Python 分析逻辑，并结合文档上下文提升分析质量。
6. 构建基础测试与 benchmark 验证机制，对系统的结构化分析能力、多表工作区分析能力和混合分析能力进行验证。

## 1.5 论文结构安排

本文共分为七章，各章内容安排如下。

第一章为绪论，介绍课题研究背景、研究意义、国内外研究现状以及本文的主要研究内容和结构安排。

第二章为需求分析，从系统目标、功能需求和非功能需求三个方面分析交互式数据分析系统需要满足的核心要求。

第三章为系统总体设计，给出系统的总体架构、功能架构及关键业务流程设计。

第四章为核心模块设计，重点介绍数据资产管理、结构化分析、文档处理、联合上下文分析以及结果沉淀等关键模块的设计思路。

第五章为系统实现，结合具体技术栈说明系统前端、后端、数据存储、检索与执行链路的实现方式。

第六章为系统测试与结果分析，通过功能测试和 benchmark 验证系统各模块的有效性，并对测试结果进行分析。

第七章为总结与展望，对全文工作进行总结，分析当前系统的不足，并展望未来的优化方向。
