# 第 3 章 系统总体设计

## 3.1 系统总体架构

本系统采用前后端分离的总体架构设计，并结合轻量数据库、文档检索机制和 AI 智能体执行链路，形成一个面向交互式数据分析场景的多层系统。系统总体上可划分为前端交互层、后端服务层、数据存储层、分析执行层和联合上下文层。

前端交互层主要由 `frontend-next` 构成，负责提供问答、工作区和数据仓三类用户界面。用户可以在问答模块中进行快速提问，在工作区模块中进行正式分析，在数据仓模块中对系统资产进行统一管理。

后端服务层基于 Spring Boot 构建，主要负责用户认证、数据集管理、工作区管理、文档管理、分析服务编排和结果沉淀等业务功能。后端通过控制器暴露 RESTful 接口，并由服务层完成具体业务处理逻辑。

数据存储层主要包含 DuckDB 和本地关系型配置存储。DuckDB 用于存放导入后的结构化数据表及部分业务元数据，支持后续分析执行；文档 chunk 元数据与工作区对象也由系统统一维护。用户认证和运行期配置信息则由本地数据库和配置文件支撑。

分析执行层主要包括 SQL 执行路径与 Python 执行路径。对于适合结构化查询的问题，系统生成 SQL 并在 DuckDB 中执行；对于适合灵活处理的问题，系统生成 Python 代码并交由受限执行器运行。

联合上下文层用于在分析前收集问题所需的多源上下文信息，包括数据表结构、表关系、工作区描述、文档检索结果和历史分析结果等。该层是结构化与非结构化联合分析能力的关键基础。

## 3.2 系统功能架构

从功能视角看，系统可划分为以下几个核心模块。

### 3.2.1 问答模块

问答模块面向轻量级探索式分析场景，允许用户通过自然语言直接提出问题，并在需要时快速上传数据。该模块更强调“快速开始”和“低门槛交互”，适合作为系统的初始入口。

### 3.2.2 工作区模块

工作区模块是系统的核心分析阵地。通过工作区，用户可以将多个数据表和多个文档组织在同一上下文中，并在此基础上进行正式的、多轮的联合分析。该模块承担了上下文组织、关系维护和历史结果沉淀等功能。

### 3.2.3 数据仓模块

数据仓模块用于统一展示和管理系统中的核心资产，包括数据表、文档、工作区和分析结果。该模块与后端对象保持较为直接的一一对应关系，是系统内部资产的总入口。

### 3.2.4 文档处理模块

文档处理模块负责接收 TXT、Markdown、PDF、DOCX 等非结构化文件，提取其中的正文内容，并按照一定规则切分为可检索的 chunk，为后续工作区分析提供知识支持。

### 3.2.5 智能分析模块

智能分析模块负责理解用户自然语言问题，结合结构化表信息与文档上下文生成分析方案，并在 SQL 或 Python 路径上执行，最终输出摘要、结果表格和执行代码。

### 3.2.6 结果沉淀模块

结果沉淀模块用于保存分析过程和结果，包括用户问题、生成的 SQL 或 Python、结果摘要、预览数据和关联上下文。其核心目标是使分析结果从一次性输出转变为可回看、可复用的资产。

## 3.3 关键业务流程设计

### 3.3.1 结构化数据分析流程

结构化数据分析流程如下：

1. 用户上传 CSV 或 Excel 文件。
2. 系统对文件进行解析，并导入 DuckDB 中形成内部表。
3. 系统提取表结构信息和元数据。
4. 用户在问答或工作区中输入自然语言问题。
5. 系统将问题与表结构信息一起发送给 AI 智能体。
6. 智能体生成 SQL 或 Python 分析逻辑。
7. 系统执行生成的逻辑并返回结果。
8. 结果以摘要、表格、代码等形式展示，并可保存为 artifact。

### 3.3.2 文档处理与检索流程

文档处理与检索流程如下：

1. 用户向工作区上传文档文件。
2. 系统识别文档类型并提取文本内容。
3. 系统对长文本进行 chunk 切分。
4. chunk 信息与文档元数据一起存储。
5. 当用户发起分析请求时，系统根据问题在当前工作区内检索相关文档片段。
6. 检索结果作为分析上下文的一部分参与后续推理。

### 3.3.3 联合分析流程

联合分析流程如下：

1. 用户在工作区中提出分析问题。
2. 系统识别当前工作区内的数据表、文档、关系和描述信息。
3. 系统根据问题类型决定是否需要召回文档上下文。
4. 系统将表结构、关系、工作区描述和文档片段统一组装为分析上下文。
5. AI 智能体根据上下文生成分析方案。
6. 系统执行分析方案并返回结果。
7. 最终结果被展示并沉淀为可复用资产。

## 3.4 设计特点

本系统的总体设计具有以下几个特点。

首先，系统以工作区为核心组织单元，将结构化数据表、非结构化文档和分析结果统一纳入上下文空间，而不是将它们视作相互独立的对象。

其次，系统采用结构化分析与文档检索并行发展的思路，使用户既能够进行传统数据查询，也能够借助业务文档提升分析解释质量。

再次，系统引入 AI 智能体作为分析中枢，使其承担问题理解、分析路径生成和结果反馈等任务，从而形成更加自然的交互式分析体验。

最后，系统在设计时保留了评测与演进空间，通过 benchmark 与 harness 机制为后续能力扩展、效果对比和系统优化提供支持。
