# 第 4 章 核心模块设计

## 4.1 数据资产管理模块设计

数据资产管理模块负责统一管理系统中的核心对象，包括数据集、文档、工作区和分析结果。该模块的设计目标是为后续分析过程提供稳定、清晰、可追踪的资产基础。

在结构化数据方面，系统将上传后的 CSV 和 Excel 文件转换为内部数据集对象，并在 DuckDB 中生成对应的物理表。每个数据集包含名称、表名、行数、列数、描述信息和所属工作区等属性。

在非结构化数据方面，系统将上传的文档抽象为文档资产对象，并进一步切分为多个文档块对象，以支持检索与上下文注入。

工作区对象承担资产组织角色，用于将数据表、文档、关系与分析结果统一纳入同一分析上下文。分析结果对象则用于保存系统执行后的关键输出。

## 4.2 结构化数据分析模块设计

结构化数据分析模块主要负责结构化数据的导入、元数据提取和分析执行。其流程包括文件上传、数据解析、表创建、字段信息获取和后续分析执行。

当用户上传表格文件后，系统首先对文件类型进行识别，并使用相应方式读取内容。读取成功后，系统将数据导入 DuckDB，并生成内部表名。随后，系统统计表的行数、列数，并提取基础字段信息，形成数据集元数据。

在分析阶段，系统根据用户问题和表结构信息调用 AI 智能体生成 SQL 或 Python 代码，并由后端执行层完成计算。该模块在系统中承担“将原始数据变成可分析对象”的核心职责。

## 4.3 非结构化文档处理模块设计

非结构化文档处理模块用于接收文本类文件，并将其转换为可检索、可参与分析的上下文单元。该模块支持 TXT、Markdown、PDF 和 DOCX 等多种文档格式。

文档上传后，系统根据文件类型调用不同解析器提取正文。提取完成后，系统对正文进行清洗与切分，将长文本划分为多个语义相对完整的 chunk。每个 chunk 记录文档标识、块序号和文本内容，并可进一步用于关键词检索或向量检索。

为提高系统可维护性，文档模块还记录处理状态，例如已上传、解析中、解析完成和解析失败等，从而方便前端展示与后续错误排查。

## 4.4 联合上下文分析模块设计

联合上下文分析模块是本系统区别于传统单表问答分析工具的重要组成部分。该模块的核心目标是：在用户提出分析问题时，不仅利用结构化表信息，还引入工作区描述、表关系和非结构化文档片段，共同构成分析上下文。

在工作区内发起分析请求时，系统首先收集当前工作区内的表结构信息、数据集描述信息和关系信息。随后，系统根据用户问题对当前工作区文档进行检索，召回可能相关的文档片段。系统再将这些信息按照一定策略组织成统一上下文，并交由 AI 智能体生成分析逻辑。

该模块的价值在于：用户提出的问题不再仅基于表格中的数值进行理解，而是能够结合业务说明和规则口径进行解释，从而提升分析结果的业务一致性与可解释性。

## 4.5 结果沉淀与管理模块设计

结果沉淀与管理模块用于保存分析过程及结果，使系统输出不再停留于一次性回复，而是成为后续可回看、可复用的分析资产。

系统在分析完成后，将用户问题、生成的 SQL 或 Python、摘要文本、结果预览和关联上下文信息保存为 artifact。前端可以在工作区或问答页面查看最近的 artifact，并将历史结果重新回填为当前分析输入。

该模块使系统具备了一定的平台属性。一方面，分析结果能够被长期保留；另一方面，历史结果也可以成为后续分析的参考对象，为持续分析工作流提供支撑。
