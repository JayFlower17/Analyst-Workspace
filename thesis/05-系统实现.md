# 第 5 章 系统实现

## 5.1 前端实现

系统前端采用基于 React 与 Next.js 的实现方式，主要负责问答、工作区和数据仓三大功能界面的呈现与交互逻辑处理。

问答模块主要提供快速分析入口。用户可在输入框中直接输入自然语言问题，并通过附加控件选择数据集、上传数据文件或将当前会话升级为工作区。系统分析完成后，在页面中展示问题对应的结果与摘要。

工作区模块作为正式分析主界面，承担多数据源联合分析任务。页面中支持工作区切换、分析问题输入、结果展示、历史结果回看，以及数据表、文档和关系等附属资源的弹窗式管理。

数据仓模块负责展示系统中的全部资产，包括数据表、文档、工作区和分析结果。该页面更偏管理视角，便于用户从全局角度理解系统内部对象。

## 5.2 后端实现

系统后端基于 Spring Boot 构建，采用控制器、服务层和数据访问层分离的方式组织代码。

控制器层负责接收前端请求并返回统一格式响应。例如，认证控制器负责登录与注册；数据集控制器负责上传、列表查询与描述更新；工作区控制器负责工作区、关系和分析相关请求；文档控制器负责文档上传、查询与删除。

服务层封装系统的主要业务逻辑。例如，数据集服务负责解析上传文件并导入 DuckDB；文档服务负责解析文档并切分 chunk；分析服务负责整合上下文、调用 AI 模型并执行分析结果；artifact 服务负责查询和管理分析结果记录。

数据访问层则主要负责与底层 DuckDB 或其他存储结构交互，为服务层提供数据访问能力。

## 5.3 数据存储实现

在数据存储实现方面，系统主要使用 DuckDB 作为结构化数据分析引擎。DuckDB 负责保存导入的数据表，并支持后续 SQL 查询和部分元数据管理。

结构化数据在上传后被导入 DuckDB，对应生成内部数据表。系统同时记录数据集名称、表名、行列统计信息和描述信息。

文档在解析后不会直接以原始形式参与分析，而是会被切分为多个 chunk，并在系统中维护文档块记录。这样既便于检索，也便于在后续阶段接入向量化检索能力。

此外，系统也保留了用于运行期管理的用户认证与会话信息存储，用于支撑登录和基本业务状态维护。

## 5.4 文档检索实现

文档检索模块支持两类基础检索方式：一类是基于关键词的 lexical 检索，另一类是面向向量模式的召回机制。在本地开发环境下，系统可优先使用 lexical 检索作为降级路径；在启用向量模式后，可进一步结合 embedding 和向量库完成更强语义召回。

当用户在工作区中发起问题时，系统会基于当前问题在工作区内检索相关文档块，并返回文档名称、块内容、分数和检索模式等信息。为提高检索质量，系统还实现了基础去重、相邻块合并和轻量 rerank 机制。

## 5.5 分析执行实现

分析执行实现由分析服务和执行层共同完成。系统接收到用户问题后，会先判断问题所处环境，例如当前是问答模式还是工作区模式，是否存在结构化数据上下文，是否需要引入文档上下文。

随后，系统调用 AI 智能体生成分析逻辑。对于适合结构化查询的问题，系统生成 SQL 并在 DuckDB 中执行；对于需要更复杂处理的问题，系统生成 Python 代码并交由受限执行器运行。

执行完成后，系统将结果组织为统一响应结构，返回前端进行展示。响应中通常包括结果数据、摘要信息、生成代码及可能的推荐图表类型等内容。系统还会将结果保存为 artifact，用于后续回看和复用。
